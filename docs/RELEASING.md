# Сборка и релиз на GitHub

Локально собирать EXE для публикации больше не требуется.

1. Внести изменения в `main`, увеличить `<Version>` в `MacroClicker.csproj` (например, `2.1.6`).
2. Добавить описание версии в `docs/releases/2.1.6.md` и обновить встроенную инструкцию при необходимости.
3. Открыть **Actions → Build and release Windows → Run workflow**, выбрать **main**.
4. Оставить **Publish a new release** включённым и нажать **Run workflow**.
5. Дождаться зелёных `build` и `release`. Новый EXE появится в **Releases**.

Альтернатива: отправить тег `v2.1.6` на коммит с такой же версией проекта.
Не нужно заранее вручную создавать релиз: это сделает workflow.
Обычные коммиты не запускают публикацию. Запуск из форков заблокирован проверкой имени репозитория.

Чтобы только проверить сборку, снять **Publish a new release**. Результат будет
в **Artifacts** этого запуска на 14 дней, без нового тега и релиза.

Сборка использует GitHub-hosted Windows, .NET SDK 8 и Node.js 24. Выполняются
проверки движка/хранилища/записи и все `tests/Web*.cjs`, затем self-contained
Windows x64 publish и проверка версии EXE. В релиз входят только EXE, инструкция
и SHA256; исходные архивы добавляет GitHub автоматически.

Сборочный job имеет только чтение репозитория. Отдельный job публикации получает
временный `GITHUB_TOKEN` с `contents: write`, не запускает код приложения и не
требует личного токена или новых секретов. Сторонние участники не получают права записи.
Версии официальных Actions закреплены полными SHA коммитов.

Опубликованные релизы не перезаписываются. Если номер уже занят — увеличьте его.
Если загрузка оборвалась, остаётся неопубликованный draft. Проверьте его и файлы
в завершённой сборке; перед повтором удалите только этот незавершённый draft
(не опубликованный релиз). Существующий тег на другом коммите workflow не меняет.

Ошибка любого теста, NuGet restore/audit, упаковки или проверки контрольных сумм
останавливает публикацию. Подробности: **Actions → нужный запуск → красный шаг**.
Проверки ввода и окон на реальной Windows-машине остаются ручными.
