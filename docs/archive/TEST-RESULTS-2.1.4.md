# Проверка сборки MacroClicker 2.1.4 — 2026-09-09

## Ввод сочетаний и тема (2.1.4)

`node tests/WebKeyCapture.cjs` — проверки production-JS: комбинации, модификаторы без основной клавиши,
русская раскладка по code, NumPad, Enter/Tab/Esc, Oemplus, повтор/порядок отпускания,
модификатор, удерживаемый до захвата, неизвестная клавиша, синхронизация темы.
Обработчики редактора проверяются с минимальными DOM doubles: применение, отмена, потеря фокуса,
неизвестная клавиша, отсутствие перехвата Ctrl+S обработчиком сохранения при захвате.
WebView2 Profile.PreferredColorScheme выставляется до навигации и при сообщении themePreview;
сохранение темы также применяет значение, отмена настроек отправляет сохранённую тему.
Нативные popup/datalist и перехват системных сочетаний Windows на Mac не проверены.

В браузерном предпросмотре проверено размещение поля, кнопки и подсказок; ручной ввод Ctrl+Shift+S.

## Фильтрация записи (2.1.4)

Фильтрация и сборка результата вынесены в production-класс RecordingSession; InputRecorder передаёт ему
события клавиатуры/мыши, HWND активного окна и окна под курсором. Список назначенных управляющих сочетаний
копируется из настроек при старте. Начальные удержания берутся через GetAsyncKeyState до установки hooks.

`dotnet run --project tests/EngineChecks.csproj -c Release` — 36 прежних проверок и 29 проверок записи.
Покрыты собственное окно, целевой/посторонний HWND, activation-click и drag, сиротские Up,
ввод до старта, F10/повторы, назначенные start/stop и другой набор модификаторов,
Ctrl+C, Alt+Shift, Win+Space, Tab/Shift+Tab, обычное/модифицированное перетаскивание,
повторное использование модификаторов после служебного жеста без удаления прежнего рабочего ввода,
Alt+Tab/Alt+Shift+Tab/Win+Tab и смена foreground до события Tab, фокус A → B и A → MacroClicker → A,
отпускание вне окна, отсутствие пауз за время в MacroClicker, резерв завершения удержаний у лимита.

Тестируется настоящий RecordingSession с поданными событиями и временем. Источник физического ввода,
GetAsyncKeyState, HWND/hit-testing, hooks и системные глобальные горячие клавиши на Mac не исполнялись.
Имена виртуальных клавиш в тесте заменены числовыми обозначениями; Windows-отображение клавиш не проверяется этим набором.
Реальные тесты пользователь выполнит позднее; отдельный чек-лист добавлен в WINDOWS-CHECKLIST.md.
Фильтр не блокирует физический ввод в Windows и не меняет сохранённые ранее макросы.

## Исправление блокировки страницы и журнал (2.1.2)

RUNTIME: на присланном скриншоте 2.1.1 среда и контроллер WebView2 созданы успешно (Runtime 153.0.4234.19 beta),
после этого `NavigationStarting: blocked` → `NavigationCompleted: success=False; status=OperationCanceled`.
CODE: старый фильтр разрешал только буквальную строку `about:blank`; журнал не содержит фактический URI события.
Причина отмены установлена — собственный фильтр приложения. Конкретное значение старого URI не установлено.

Теперь используется фиксированный адрес `https://macroclicker.invalid/index.html` и ответ из встроенного ресурса
через WebResourceRequested. Страница не скачивается с сайта и не извлекается в отдельный HTML-файл.
Один и тот же адрес проверяется для навигации, ответа и native bridge; прочие запросы получают 403,
посторонние переходы и редиректы запрещены. Отмена другой навигации не переводит уже загруженный интерфейс в ошибку.
Механизм: [Microsoft — local content / WebResourceRequested](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/working-with-local-content#loading-local-content-by-handling-the-webresourcerequested-event).

Проверки `dotnet run --project tests/EngineChecks.csproj -c Release` — PASS 36/36: 27 проверок движка, 6 политики страницы,
3 журнала (сохранение ошибок, отказ файловой системы с сохранением снимка в памяти, параллельная запись).
Политика проверяется настоящим production-классом; Win32/WebView2 на Mac не исполняются.
`node tests/WebStartupChecks.cjs` — PASS 7/7: ранние ошибки и подтверждение render.
Браузерный предпросмотр: пункт «Журнал», открытие модального окна, текст, обновление/копирование/папка как элементы интерфейса;
визуально проверено оформление. Реальный буфер обмена и открытие папки на Windows не проверялись.
Окончательное подтверждение загрузки, анимации нативного лоадера и системного буфера обмена требует Windows.

## Диагностика серого окна (2.1.1)

На тестовой Windows-машине пользователь сообщил о пустом сером окне при установленном WebView2.
На момент выпуска 2.1.1 причина была UNKNOWN: журнал предыдущей версии не создавался, Windows-хост на Mac не запускается.
В 2.1.1 добавлены независимая от HTML нативная панель запуска, предел ожидания 25 секунд,
журнал этапов создания среды/контроллера, NavigationCompleted/WebErrorStatus, ProcessFailed,
ранние ошибки JavaScript и подтверждение первого render после получения начальных данных.
Горячая клавиша запуска до подтверждения render заблокирована. Профиль, настройки и макросы не удаляются.

Проверки JavaScript: `node tests/WebStartupChecks.cjs` — 7 сценариев: синтаксис обоих скриптов,
ранняя ошибка, необработанный Promise без содержимого reason, отсутствие native bridge,
подтверждение после render, отсутствие повторного подтверждения, отсутствие подтверждения при ошибке render.
Это проверка реального обработчика сообщений с заменой DOM-функций; она не подтверждает отрисовку WebView2 на Windows.
Проверка 2.1.1 пользователем дала причину блокировки, описанную выше. В 2.1.2 журналы имеют имя `session-*.log`.

## Проверка нового интерфейса на Mac

Через локальный браузер открыт настоящий Web/index.html, который встраивается в Windows-сборку. Использовался явно отмеченный режим предпросмотра, без Windows API и файловой библиотеки.

- Создание узла без выбора приложения; подсказка про 5 секунд видна.
- Редактирование имени и добавление отдельного двойного клика; сохранённый узел виден в карточке.
- Переход «Сценарий → JSON» показывает UseActiveWindow: true и Kind: DoubleClick.
- Некорректный JSON блокирует возврат к сценарию; восстановление корректного JSON возвращает карточку без потери шага.
- Переключатель раздельных сочетаний добавляет второй блок; применение отражает оба сочетания в панели запуска.
- Светлая тема применяется; проверены геометрия и отсутствие горизонтального переполнения при 900×640. Кнопка применения и кнопка запуска находятся в пределах окна.

WebView2-хост, реальные горячие клавиши, отсчёт 5 секунд и работа Windows-ввода проверкой браузерного предпросмотра НЕ подтверждены.

MSB3277 при первом подключении WebView2 был вызван лишней ссылкой Microsoft.Web.WebView2.Wpf.dll, которую пакет добавляет и в WinForms-проект. Неиспользуемая WPF-ссылка исключена до ResolveAssemblyReferences; предупреждение не подавлялось. Сборка с -warnaserror завершилась успешно.

Проверки используют настоящий MacroRunner.cs и MacroModels.cs, но заменяют Windows API и парсер клавиш тестовыми реализациями. Они не подтверждают работу перехватчиков, физической клавиатуры, смены раскладки, конкретного приложения или отрисовки WinForms.
