# Запуск MacroClicker

Версия 2.1.2: исправлена блокировка собственной страницы при старте, добавлены лоадер и журнал.
Для ошибок после запуска откройте «Журнал» слева → «Копировать» либо «Папка журналов».
Для каждого запуска сохраняется `%LOCALAPPDATA%\MacroClicker\Logs\session-*.log`.

1. Скопируйте папку MacroClicker-Windows на локальный диск Windows.
2. Запустите MacroClicker.exe. .NET устанавливать не требуется. Если отсутствует WebView2 Runtime, однократно установите его из Runtime/MicrosoftEdgeWebView2RuntimeInstallerX64.exe и повторите запуск; установщик работает офлайн.
3. Откройте нужные приложения.
4. Создайте макрос и добавьте узел. Можно выбрать приложение или оставить «Текущее активное окно».
5. Добавьте действия через «Редактировать». Сохраните макрос.
6. Нажмите «Старт» или Ctrl+Alt+F8. Явно назначенные окна активируются по порядку. Для узлов активного окна перед запуском идёт отсчёт 5 секунд — перейдите в нужное приложение.
7. Повторное нажатие останавливает сценарий.

Если целевое приложение работает от администратора, запустите MacroClicker с теми же правами.

Инструкция по JSON, записи, тексту и системным паузам встроена в EXE: кнопка «Справка» слева внизу.

## Сборка на Mac

В папке проекта:

    ./build-macos.sh

Скрипт использует установленный SDK /Users/lyapunov-a/.dotnet/dotnet и создаёт publish/MacroClicker.exe для Windows x64.

Сначала выполняется явное восстановление зависимостей с включённым NuGet Audit, затем публикация. Для получения свежих данных аудита нужен доступ к api.nuget.org. При NU1900 исправьте сетевой доступ и повторите скрипт; отключать аудит не нужно. Из ограниченной среды сборку необходимо запускать с разрешённым сетевым доступом.

## Сборка на Windows

Установите .NET 8 SDK и выполните в папке исходников:

    powershell -ExecutionPolicy Bypass -File .\build-windows.ps1

После сборки запустите publish\MacroClicker.exe.
